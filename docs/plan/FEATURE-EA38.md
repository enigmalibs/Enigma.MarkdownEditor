# FEATURE-EA38 — New application icon

**Status:** DONE
**Type:** FEATURE · single phase · Roadmap: `docs/roadmap.md` · **Branch:** `feature/feature-ea38-new-app-icon`, cut from the run branch at build time.
**Run:** feature/2026-10-28-new-icon-release

## Objective

Replace the application's icon everywhere it ships with the new artwork the user dropped into the
temporary, untracked `new-icons-remove-when-done/` directory, then delete that directory. The new
mark is the *MD-A2 Outline* design: a dark rounded square holding an outlined `M↓` box, blue `M`,
green arrow. It replaces the solid blue square with a white `M↓`.

## Context & constraints

- **Three places carry the icon today**, all binary and all referenced by path:
  - `src/Enigma.MarkdownEditor.Desktop/Assets/app.ico` — `<ApplicationIcon>` in the Desktop csproj
    (the Windows `.exe` resource), `Icon=` in `Views/MainWindow.axaml` (the running window, every
    platform), and `productIcon` / `iconPath` in all ten committed `msiProfiles/*.msipkg.json`;
  - `src/Enigma.MarkdownEditor.Desktop/Assets/app-256.png` — the `Image` in `Views/SplashWindow.axaml`
    and `Views/AboutView.axaml`;
  - `packaging/linux/icons/enigma-markdown-editor-{16,32,48,64,128,256}.png` — installed into
    `hicolor/<N>x<N>/apps/` by `install.sh`, removed by `uninstall.sh`, packed by `pack-linux.ps1`.
    The three scripts keep one size list each and "the three lists move together".
- **The new set** (`new-icons-remove-when-done/`): `enigma-markdown-editor.ico` (10 PNG-compressed
  frames, 16 … 256), `enigma-markdown-editor-<N>.png` for N = 16 20 24 32 40 48 64 96 128 256, and two
  SVGs. The SVGs' own header says they, the PNGs and the `.ico` are all generated by
  `python3 Branding/Apps/export.py` in the branding repository — the masters live there.
- **The directory is untracked**, so deleting it is a filesystem delete, not a git change.
- `Assets/**` is an `AvaloniaResource` glob: anything dropped in `Assets/` is embedded.
- The headless test platform draws without Skia, so a test cannot decode an image; it can read an
  asset's bytes through `AssetLoader`.

## Design

1. Copy, keeping every existing file name:
   - `enigma-markdown-editor.ico` → `Assets/app.ico`;
   - `enigma-markdown-editor-256.png` → `Assets/app-256.png`;
   - `enigma-markdown-editor-<N>.png` → `packaging/linux/icons/enigma-markdown-editor-<N>.png` for the
     six sizes the installer already ships.
2. Verify each copy with `cmp` against its source, then `rm -r new-icons-remove-when-done/`.
3. Add `tests/Enigma.MarkdownEditor.Desktop.UnitTests/AppIconTests.cs`, reading the embedded assets:
   - `app.ico` is an icon resource (`reserved = 0`, `type = 1`) whose directory lists at least the
     16, 24, 32, 48 and 256 frames, each frame's bytes inside the file;
   - `app-256.png` is a PNG whose `IHDR` says 256 × 256.
4. No markup, csproj, script or MSI profile change: every path stays the same.

## Acceptance criteria

- The eight tracked icon files are byte-identical to their sources in the new set.
- `new-icons-remove-when-done/` no longer exists; `git status` shows no trace of it.
- `AppIconTests` passes, and the existing `TheIcon_IsAResourceThatResolves` tests (Splash, About)
  still do.
- Release build: 0 warnings, no `AVLN`; full suite green.

## Out of scope

Shipping the 20/24/40/96 PNGs on Linux · a `scalable/apps` SVG on Linux · committing the SVGs ·
rendering an SVG in-app · regenerating the art · the release itself (`FEATURE-977D`).

## Decisions taken autonomously

| Question | Chosen | Why | Alternatives rejected |
|---|---|---|---|
| Rename the files to the new set's names? | No — new bytes, old names | Every reference stays valid, including ten historical MSI profiles that must not be edited | Renaming to `enigma-markdown-editor.*` and updating csproj, three views, scripts and the latest profile |
| Ship the extra 20/24/40/96 PNGs on Linux? | No | They are frames inside the new `.ico`, where Windows uses them. On Linux the six installed sizes and the 256 frame cover the launcher. Adding sizes would change three scripts in step, and `pack-linux.ps1` cannot run here (no `pwsh`) | Extending all three size lists to the hicolor sizes the set covers |
| What happens to the SVGs? | Not committed; deleted with the directory | They are generated outputs whose masters live in the branding repository. Avalonia cannot draw SVG without a new package. A Linux `scalable` icon would add a third install path to verify for little gain over the 256 px PNG | Committing them as source art; installing `scalable/apps/enigma-markdown-editor.svg` |
| Add a test? | Yes — `AppIconTests` over the embedded bytes | A binary swap can ship a truncated or wrong-sized asset with nothing failing: the existing tests only check that the PNG resolves, and nothing reads the `.ico` | No test; a Skia-backed decode (the suite deliberately stays off Skia) |
| Pre-flight found the input directory untracked | Proceed | It is this spec's input, not uncommitted work of the user's | Stopping on a dirty tree |
