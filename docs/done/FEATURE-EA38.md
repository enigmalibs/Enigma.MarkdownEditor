## Summary

The application has its new icon everywhere it ships. The new mark is a dark rounded square holding
an outlined `M↓` box, with a blue `M` and a green arrow. It replaces the solid blue square with a
white `M↓`.

Eight tracked files received the new bytes **under their existing names**:

- `Assets/app.ico` — the window, the `.exe` and the MSI shortcuts;
- `Assets/app-256.png` — the splash and the About dialog;
- the six Linux launcher sizes.

No markup, csproj, script or MSI profile changed. Each copy was checked byte-identical (`cmp`) to
its source before the temporary `new-icons-remove-when-done/` directory was deleted.

`AppIconTests` now reads both embedded assets as bytes, so a truncated or wrong-sized export fails
the suite.

## Decisions taken at build time

| Question | Chosen | Why |
|---|---|---|
| Where `AppIconTests` lives | Test project root, beside `ProgramSmokeTests` | It covers assets, not a view, a ViewModel or a service, so no existing folder fits |
| Which frames the test requires | 16, 24, 32, 48, 256 | The sizes the Windows shell asks for at 100 % and 150 % plus Explorer's medium and jumbo views. Requiring all ten would fail on a legitimate re-export with fewer frames |
| Documentation sweep | No edit | The README and `docs/RELEASE.md` mention "the icon" and its paths but never what it looks like, and every path is unchanged |
